# Story 2.1: Add `mapping` Column Migration

## Story Goal

Add a JSON column to the `data_imports` table to persist user-defined column mappings during CSV import, enabling advanced field mapping functionality.

**Why:** The Contact Import system was enhanced with column mapping capabilities, but the database migration to store the mapping was never created. Without this column, the mapping data cannot be persisted, breaking the entire import feature.

---

## Story Description

### Problem Statement

The `DataImport` model contains `serialize :mapping, JSON` (line 23 in `app/models/data_import.rb`), but the corresponding database column does not exist in the `data_imports` table. This causes:

1. Frontend sends mapping data to backend
2. Backend attempts to save it: `create!(data_type: 'contacts', mapping: mapping)` (line 60 in contacts_controller.rb)
3. Rails silently ignores the attribute (or errors) because the column doesn't exist
4. Job receives `nil` as mapping when attempting to process the CSV
5. Import fails silently or creates invalid contacts

### System Context

**Related Components:**
- Model: `app/models/data_import.rb` (line 23: `serialize :mapping, JSON`)
- Controller: `app/controllers/api/v1/accounts/contacts_controller.rb` (line 60: creates with mapping)
- Job: `app/jobs/data_import_job.rb` (line 13: uses mapping)
- Service: `app/services/data_import/contact_manager.rb` (expects mapping)

**Technology Stack:**
- Database: PostgreSQL 12+
- ORM: ActiveRecord 7.0
- Rails: Rails 7.0

**Current Schema:**
```ruby
# Current data_imports table (from db/schema.rb)
create_table "data_imports", force: :cascade do |t|
  t.bigint "account_id", not null
  t.string "data_type", not null
  t.integer "status", default: 0, not null
  t.text "processing_errors"
  t.integer "total_records"
  t.integer "processed_records"
  t.datetime "created_at", not null
  t.datetime "updated_at", not null
  t.index ["account_id"], name: "index_data_imports_on_account_id"
end
```

**Missing Column:**
```ruby
t.json :mapping, default: {}  # ← NEEDS TO BE ADDED
```

## Implementation Notes

### Migration Details

**File Location:**
```
db/migrate/20260502_add_mapping_to_data_imports.rb
```

**Migration Class Name:**
```ruby
class AddMappingToDataImports < ActiveRecord::Migration[7.0]
```

**Column Specification:**
```ruby
def change
  add_column :data_imports, :mapping, :json, default: {}, unless: column_exists?(:data_imports, :mapping)
end
```

**Key Points:**
1. Use `unless: column_exists?()` to make migration idempotent
2. Default value is empty hash `{}` (not nil)
3. No index needed initially (will add later if query performance requires)
4. Native JSON type (not JSONB) is sufficient for this use case

### Related Code

**Where mapping is used:**
- Line 23 in `app/models/data_import.rb`: `serialize :mapping, JSON`
- Line 60 in `app/controllers/api/v1/accounts/contacts_controller.rb`: `create!(data_type: 'contacts', mapping: mapping)`
- Line 13 in `app/jobs/data_import_job.rb`: `DataImport::ContactManager.new(account, mapping)`
- Lines 3-7 in `app/services/data_import/contact_manager.rb`: Constructor expects mapping parameter

## Decision Log

**Decision 1: JSON vs JSONB**
- **Chosen:** JSON (native type)
- **Rationale:** Adequate for this use case, simpler column definition
- **Alternative:** JSONB offers better query performance but overkill for simple storage

**Decision 2: Default Value**
- **Chosen:** Empty hash `{}`
- **Rationale:** Matches existing behavior where mapping defaults to empty
- **Alternative:** NULL - rejected because model expects Hash

**Decision 3: Index**
- **Chosen:** No index in this migration
- **Rationale:** Will add if query performance requires it
- **Alternative:** Add now - premature optimization
