## Technical Audit

### Backend
- **Search Performance**: The use of `ILIKE` in `Conversation` is efficient due to the existing GIN index on `contacts` (name, email, phone).
- **Security**: No SQL Injection vulnerabilities found; uses ActiveRecord named parameters.
- **Automation Logic**: `CrmListener` is safe from simple recursion as it returns early if `label_list` is not changed.

### Frontend
- **Store Architecture**: Pinia store `crmPipeline` is well-structured, managing filter state globally and handling pagination resets correctly.
- **Component Design**: `FilterBar.vue` is clean and uses Tailwind as per project rules.
- **Performance**: Search is correctly debounced to 300ms to avoid API hammering.

## Observations & Recommendations
1.  **Labels UX**: Currently, users must type labels manually. For the next iteration, I recommend replacing this with a proper `LabelSelector` component for better discoverability.
2.  **Error Handling**: The store `catch` blocks are currently silent. It is recommended to add toast notifications for failed stage movements.
3.  **Automation Customization**: The "Qualified" stage name is currently hardcoded in the listener. Consider making this configurable per pipeline in future stories.
